# 📁 Worked Examples

> **The rules tell an agent what to do. These files show what "done" looks like.**

A placeholder prompt (`SUBJECT: [main object]`) gets filled in generically, and generic is exactly the AI look the rules exist to prevent. Every prompt in this folder is **finished** — no brackets, no `[BRAND]`, nothing left for the model to invent.

## How each case is structured

```
1. BRIEF            — what the client actually said, including what they got wrong
2. CREATIVE WORK    — R28 steps 1–10, worked, with the reasoning visible
3. HEADLINE         — five drafts, three killed, one shipped, and why
4. THE PROMPT       — the finished prompt, copy-pasteable, zero placeholders
5. WHAT CAME BACK   — first-pass result and its QA score
6. THE FIX          — what changed on the second pass and why
7. WHAT TO STEAL    — the transferable part
```

## Honest note on these examples

The briefs, prompts, headlines and QA verdicts here are **composites drawn from real production campaigns** (coastal hospitality and local-trade clients), reconstructed so they can be published without exposing client assets. The rejection modes are the real ones — every "what came back" failure in these files is a failure that actually happened and got fixed. No rendered images are committed, because the client photography they were built on isn't ours to publish.

Use them as templates for structure and specificity, not as claims about any named business.
