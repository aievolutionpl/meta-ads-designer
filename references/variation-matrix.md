# Creative Variation Matrix

> The operating tool behind **R35**: turn one promise into a test-ready set of ads — lock the brand, rotate one axis at a time, and know exactly what you changed and why.

An ad campaign is **a set built for testing**, not a single hero image. The variation matrix is the structure that makes that testing legible: what never changes (brand-lock) and what changes by design (the test axes).

---

## 1 · The idea

A matrix is a grid. Rows are **locked elements** (the same in every cell). Columns are **one rotating axis** — one thing that differs between variants so that when results come back, you can name the variable that moved them.

> `1 locked promise × 1 rotating axis × N variants`, never `N unrelated ads`.

A colour swap is not a variant (R21). A variant differs by the **promise or mechanism it tests**. The matrix forces you to decide *which* difference you are testing before you spend on generating it.

---

## 2 · What stays locked

These are the **brand-lock** rows — identical across every variant so the set reads as one campaign (R20) and the test is clean:

- **Product** — exactly the reference, unchanged (R03).
- **Logo** — the official file, never AI-redrawn (R30-logo).
- **Brand palette** — one accent allowed, never the purple/blue default (R05).
- **Core promise** — the single benefit the whole set is built on (R06).
- **Headline intent** — the meaning the headline must land, even if the wording varies.

---

## 3 · The five test axes

Pick **one** of these to rotate in a given set. Each is a hypothesis about *what will stop the scroll*:

| Axis | What varies | What it tests |
|------|-------------|---------------|
| **Hook** | Opening line / wording | Does the promise land in 1 second? (R36) |
| **Visual metaphor** | Hero image, scene, metaphor | Which picture sells the benefit best? (R14, R24) |
| **Format** | Static vs. video/UGC vs. carousel, ratio | Where does the audience engage? (R38, R39) |
| **Lifestyle scene** | Who/where the product is shown in use | Which audience self-identifies? (R12) |
| **Emotion / angle** | Problem → Effect → Lifestyle | Which buying motive converts? (R13) |

**Never rotate two axes in one variant.** If variant A changes both the hook and the scene, a win doesn't tell you which one caused it.

---

## 4 · Reading the matrix

For a single promise, a minimal test set looks like:

```
PROMISE: "Convenience — reach your stuff without a step ladder"
 LOCKED: product (unchanged), logo, palette, one accent, headline intent
 ┌─────────────┬───────────────────────┬────────────────────────────┐
 │ ROTATING    │ Variant 1             │ Variant 2                  │
 ├─────────────┼───────────────────────┼────────────────────────────┤
 │ Visual      │ Hero: shelf in a      │ Hero: hand pulls the shelf │
 │ metaphor    │ bright minimal kitchen│ down at eye level          │
 │ (R24)       │                       │                            │
 │ Headline    │ "Within easy reach"   │ "The shelf comes to you"   │
 │ (R36)       │                       │                            │
 └─────────────┴───────────────────────┴────────────────────────────┘
```

The matrix is also the **record** — what you generated, what you tested, what won. Keep it; it feeds the performance loop (R37).

---

## 5 · Minimum set for a test

Before you generate:

1. **One promise**, written as a sentence the target would say.
2. **Locked elements** named explicitly (product, logo, palette, intent).
3. **One rotating axis** chosen — with a reason.
4. **3 structurally different variants** (not 3 re-colours).
5. **QA every variant** against the gate (R34) before it ships.

If you cannot name the single rotating axis, you are not ready to generate — go back to the brief.
